# ==========================================================
# CREATIVE WORKFLOW
# Version 1.2
# ==========================================================

## Philosophy

The purpose of this workflow is to improve creative reasoning.

Creative execution should be the result of deliberate reasoning rather than immediate generation or modification.

Every visual decision should be grounded in a believable world, logical relationships, material behaviour, camera logic and commercial intent.

The final image is the outcome of the reasoning process, never its starting point.



---

## Core Principle

A believable image begins with a believable world.

The world defines:

- Environment
- Physical Behaviour
- Materials
- Object Behaviour
- Lighting
- Camera
- Composition
- Spatial Relationships
- Visual Hierarchy

Creative elements should emerge naturally from the same world rather than being assembled as isolated objects.

World consistency takes priority over isolated visual detail.

A visually attractive element should not be introduced if it contradicts the physical, material, lighting, camera or commercial logic of the scene.



---

## Scope

This workflow is the standard creative reasoning process for every creative visual task.

This includes, but is not limited to:

- Image Generation
- Image Editing
- Image Analysis
- Image Retouching
- Visual Diagnosis
- Style Transformation
- Commercial Visual Design
- Product Visualization
- Food Photography
- Key Visual Development
- Packaging Visualization
- Creative Direction
- Visual Evaluation

Tasks that require creative judgement must use this workflow.

Tasks that involve only technical file operations, such as file conversion, export or metadata changes, may bypass unnecessary creative reasoning.

Technical image changes that affect composition, perspective, lighting, content or scene continuity should still use the relevant parts of this workflow.



---

## Creative Reasoning

Creative reasoning is an iterative process.

Each stage informs and refines the others until the project converges toward a single coherent solution.

A typical reasoning process includes:

1. Project Understanding
2. Creative Intent
3. World Definition
4. Physical Logic
5. Material Behaviour
6. Object Behaviour and Interaction
7. Lighting
8. Camera and Perspective
9. Composition
10. Commercial Evaluation
11. Decision
12. Execution
13. Validation

The sequence may adapt depending on the task, but reasoning should always move toward greater clarity, consistency and confidence.

No stage should be treated as an isolated checklist. A change in one stage may require corresponding changes in other stages.

For example:

- A lighting change may require updated shadows, reflections, highlights and material response.
- A camera change may require updated perspective, scale, depth and composition.
- A material change may require updated roughness, reflection, transparency, moisture and surface behaviour.
- A positional change may require updated gravity, contact, occlusion and cast shadows.



---

## Project Understanding

The project should first be interpreted as a communication problem rather than an image request.

Project understanding may include:

- Project Objective
- Brand
- Audience
- Platform
- Deliverable
- Format
- Constraints
- Required Content
- Elements That Must Remain Unchanged

The task should not proceed until the intended outcome is sufficiently clear.

When critical information is missing and cannot be safely inferred, clarification should be requested before execution.



---

## Asset Consistency Decision — Optional

After Project Understanding and before detailed world execution, determine whether the project contains a persistent visual asset. If not, select Level 0 — No Blueprint and continue unchanged. If it does, load an existing Level 1 — Lightweight Blueprint or Level 2 — Full Blueprint, or create a text Draft through Asset Intake and Reference Separation under the optional [Asset Blueprint Protocol](asset-blueprint/ASSET_BLUEPRINT_PROTOCOL.md).

After identity constraints are defined, return to the standard Creative Workflow. Asset Blueprint controls approved persistent asset identity; this workflow remains authoritative for world definition, physics, materials, object interaction, lighting, camera, perspective, composition, communication, commercial intent and scene logic.



---

## Creative Intent

Creative intent defines what the audience should notice, understand, feel or do.

Typical objectives may include:

- Attract Attention
- Create Memory
- Trigger Emotion
- Communicate Information
- Establish Brand Value
- Demonstrate Product Benefit
- Support Product Sales

Visual decisions should serve the intended communication objective rather than decoration alone.



---

## Creative Direction Handoff and Execution Readiness

A Selected Creative Direction defines intended communication and visual behaviour. Whether established directly through Creative Intent or informed by optional [Visual Translation](visual-translation/VISUAL_TRANSLATION_PROTOCOL.md), it is not an execution prompt and does not by itself authorise generation, editing, retouching or other visual execution.

A direction such as contemporary Japanese, premium but not luxurious, youthful but credible, dynamic but controlled or minimal but impactful does not establish the hero subject, deliverable, audience, commercial objective, required assets or content, world, environment, scene, camera, materials, lighting, hierarchy or composition.

Before continuing into detailed world and execution reasoning, confirm that Project Understanding is sufficient to determine, where applicable:

- Deliverable and use case
- Platform, format, ratio and viewing context
- Audience and commercial or communication objective
- Hero Subject
- Required products, assets, messages and mandatory content
- Required hierarchy, inclusions and exclusions
- Existing Scene Locks
- Active Asset Blueprint constraints
- Acceptable scope of creative inference

A ratio alone is never a complete deliverable definition. Ask only for missing information that would materially affect execution; simple, sufficiently defined projects should continue without an excessive questionnaire.

Make one explicit readiness decision:

- **Ready for Execution** — sufficient foundational information exists to continue through the remaining Creative Workflow. This decision does not bypass world, physical, material, lighting, camera, composition, commercial, strategy or validation reasoning.
- **Clarification Required** — missing information could materially redefine the hero subject, deliverable, world, composition, commercial meaning, required content, asset identity or scene logic. Request targeted clarification and do not silently invent the missing foundation.
- **Analysis / Direction Only** — the requested outcome is analysis, diagnosis, direction or planning rather than visual execution. Stop after the required analysis and execution plan.

Secondary details may be inferred when they do not redefine the project. These may include minor supporting props, subtle surface imperfections, physically necessary secondary shadows, small environmental details and non-critical styling details.

Do not silently infer foundational decisions such as the advertised product, whether the deliverable is a food key visual or an interior image, the brand, campaign message, Hero Subject, commercial objective, required copy area or primary environment category.

When readiness is confirmed, hand the Selected Creative Direction into the existing authoritative reasoning for World Definition, Physical Logic, Object Behaviour and Interaction, Material Behaviour, Lighting, Camera and Perspective, Composition, Hero Subject, visual hierarchy, Scene Locks, Variable Assets, Commercial Evaluation, Decision, Execution and Validation. This handoff does not create a second workflow.

For a direct `Build |` generation request, complete the required reasoning internally and execute only when readiness passes. When foundational information is missing, request targeted clarification rather than generating an unrelated generic visual. When the request asks for analysis first or says not to generate, stop after the requested analysis and plan in accordance with the active Build workflow.

For example, “Japanese feeling, not too traditional, premium but not luxurious, ratio 4:5” may support a contextual Selected Creative Direction, but execution requires clarification because the Hero Subject, deliverable, commercial objective, required content and world are undefined. Ask targeted questions rather than generating a generic Japanese interior. This example demonstrates the readiness principle, not a reusable visual formula.

## World Definition

The world should be established before individual visual elements are developed or modified.

World Definition may include:

- Environment
- Location
- Space
- Time
- Weather
- Atmosphere
- Story Context
- Background Distance
- Surface Relationships
- Environmental Conditions

All objects should appear to exist within the same world.

Background, subject and supporting elements should share compatible perspective, lighting, scale, atmosphere and spatial logic.



---

## Physical Logic

Every object should obey consistent physical rules.

Physical reasoning may include:

- Gravity
- Weight
- Balance
- Pressure
- Heat
- Moisture
- Wind
- Liquid Flow
- Buoyancy
- Compression
- Contact
- Support
- Occlusion

Objects should not float, intersect, penetrate or balance impossibly unless intentionally required by the concept.

Physical effects should appear where their causes exist.

For example:

- Heat affects nearby food, liquid, steam and surfaces.
- Weight affects folding, compression and support.
- Liquid follows gravity and surface boundaries.
- Contact affects shadows, moisture, deformation and staining.



---

## Material Behaviour

Materials should be defined by how they behave rather than by surface labels alone.

Material reasoning may include:

- Surface Structure
- Roughness
- Reflection
- Transparency
- Translucency
- Moisture
- Oiliness
- Temperature
- Thickness
- Porosity
- Wear
- Edge Behaviour

Different materials should respond differently to the same environment and light source.

The workflow should avoid applying the same smoothness, sharpness, gloss or texture treatment across unrelated surfaces.

Material detail should remain irregular, directional and scale-appropriate rather than appearing procedural or repetitive.



---

## Object Behaviour and Interaction

Objects should interact naturally with surrounding objects and environmental forces.

Examples include:

- Steam rising from local heat sources
- Oil spreading across liquid surfaces
- Sauce adhering differently to dry and wet surfaces
- Fabric folding according to weight and tension
- Paper wrinkling according to moisture and heat
- Food compressing where supported or pressed
- Reflections changing according to angle and material
- Shadows responding to position, distance and light direction

Behaviour should be caused by the world rather than added as a decorative effect.

Local changes should produce appropriate local consequences without unnecessarily redefining unrelated parts of the scene.



---

## Lighting

Lighting should emerge from the established environment.

Lighting reasoning may include:

- Primary Light Source
- Secondary Light
- Direction
- Intensity
- Softness
- Colour Temperature
- Shadow Behaviour
- Reflection Behaviour
- Exposure
- Contrast
- Atmospheric Effect

All objects should respond to the same lighting system.

Lighting changes should update:

- Highlights
- Reflections
- Cast Shadows
- Contact Shadows
- Translucency
- Material Appearance
- Steam Visibility
- Background Illumination

Lighting should support the communication objective without creating contradictions in the world.



---

## Camera and Perspective

Camera decisions should support both realism and communication.

Camera reasoning may include:

- Camera Position
- Camera Height
- Camera Angle
- Lens Behaviour
- Perspective
- Field of View
- Focus
- Depth of Field
- Distortion
- Subject Scale

All objects should share a compatible perspective system.

A camera or perspective change should not be treated as a local visual adjustment. It may require corresponding changes to scale, orientation, occlusion, depth and composition.



---

## Composition

Composition should organise attention and communication.

Composition reasoning may include:

- Visual Hierarchy
- Hero Subject
- Reading Direction
- Balance
- Negative Space
- Cropping
- Object Distribution
- Depth
- Rhythm
- Supporting Elements
- Text-safe Space

Composition should avoid arbitrary symmetry, uniform spacing and evenly distributed objects unless intentionally required.

The Hero Subject should remain visually dominant, while supporting elements reinforce rather than compete with it.



---

## Commercial Evaluation

A creative solution should be evaluated against its commercial purpose.

Commercial evaluation may include:

- Is the main subject immediately identifiable?
- Is the communication objective clear?
- Is the product or message memorable?
- Does the image support the intended brand value?
- Does visual hierarchy guide attention correctly?
- Is the result usable across the required platform and format?
- Does the image help communicate or sell the product?
- Does realism support rather than weaken commercial appeal?

A visually impressive result is not successful if the product, message or brand becomes unclear.



---

## Decision

Execution begins only after a clear execution strategy has been established.

The decision stage should reduce uncertainty rather than create unnecessary options.

A complete execution strategy defines:

- Project Objective
- Selected Creative Direction
- Key Visual Decision
- Scene Locks
- Variable Assets
- Visual Identity
- Execution Priority
- Elements to Preserve
- Elements to Modify

When Asset Blueprint Level 1 or Level 2 is active, the strategy should also identify the applicable Asset Version, selected Controlled Variation and Temporary State without treating the Blueprint as a complete generation prompt.

Alternative directions should remain only when they provide meaningful value or are explicitly requested.

When one direction is clearly stronger, the workflow should recommend it directly rather than presenting multiple equal options without a decision.



---

## Scene Locks

Scene Locks define the persistent elements of the project world.

Typical Scene Locks include:

- Environment
- Background
- Surface
- Camera Position
- Camera Height
- Camera Angle
- Camera Lens
- Lighting Direction
- Perspective
- Composition
- Hero Subject Position
- Global Colour Mood

Locked elements remain stable throughout future iterations unless intentionally revised.

When the user requests a local change, all unrelated Scene Locks should remain unchanged.

Scene Locks govern the current project world. Permanent Asset Locks govern intrinsic reusable asset identity. When the optional Asset Blueprint module is active, neither may silently overwrite the other; genuine conflicts must be classified and deliberately resolved under the [Asset Blueprint Protocol](asset-blueprint/ASSET_BLUEPRINT_PROTOCOL.md).



---

## Variable Assets

Variable Assets define the elements that may change while preserving the established world.

Typical Variable Assets include:

- Ingredients
- Product Quantity
- Character Pose
- Props
- Steam
- Sauce State
- Decorative Elements
- Supporting Objects
- Graphic Space
- Aspect Ratio

Changing a Variable Asset should not unintentionally redefine:

- Environment
- Camera
- Lighting
- Composition
- Perspective
- Material Logic
- Unrelated Objects

Any secondary effect caused by the change should be updated where physically necessary.

When the optional Asset Blueprint module is active, distinguish Variable Assets from approved Controlled Variations and shot-, scene- or sequence-specific Temporary State Changes. None may silently modify Permanent Asset Locks.



---

## Image Analysis

Image Analysis is a diagnostic reasoning task.

Its purpose is to identify why an image succeeds or fails, not to generate a visual analysis board unless explicitly requested.

Analysis may evaluate:

- Project Intent
- World Consistency
- Physical Logic
- Material Behaviour
- Object Interaction
- Lighting
- Camera
- Perspective
- Composition
- Visual Hierarchy
- Commercial Clarity
- AI Artifacts

Analysis should identify root causes rather than only describe visible symptoms.

The result should establish a clear correction strategy before any retouching or regeneration begins.



---

## Image Retouching

Image Retouching is a controlled refinement process.

Retouching should improve the existing image without unnecessarily rebuilding or reinterpreting the complete scene.

The sequence should be:

1. Diagnose the Image
2. Identify the Root Cause
3. Define the Retouch Strategy
4. Lock Unchanged Elements
5. Execute the Local or Global Correction
6. Validate the Result

Unless explicitly requested, retouching should preserve:

- Composition
- Subject Position
- Subject Shape
- Camera
- Perspective
- Lighting Logic
- Background
- Unrelated Objects
- Established Material Identity

A local retouch should not introduce unrelated changes.

When a requested edit affects lighting, physics or object interaction, the necessary secondary effects should also be updated to maintain consistency.



---

## Style Transformation

Style transformation should preserve the underlying world unless the user explicitly requests a redesigned environment.

The transformation should retain:

- Composition
- Spatial Relationships
- Object Identity
- Perspective
- Lighting Logic
- Physical Interaction
- Visual Hierarchy

Style should affect visual language rather than destroy scene logic.

The result should appear as the same world interpreted through a different visual system, not as an unrelated image containing similar objects.



---

## Quality Evaluation

Visual quality is determined by the credibility of interactions rather than the quantity of detail.

Every project should evaluate:

- World Consistency
- Physical Consistency
- Material Authenticity
- Object Interaction
- Lighting Consistency
- Camera Logic
- Perspective Accuracy
- Spatial Logic
- Visual Hierarchy
- Commercial Clarity
- Scene Continuity

The workflow should actively identify and reduce common AI artifacts, including:

- Repetitive Patterns
- Hidden Texture Patterns
- Uniform Object Distribution
- Plastic-looking Materials
- Excessively Smooth Surfaces
- Unrealistic Reflections
- Incorrect Perspective
- Impossible Physical Behaviour
- Inconsistent Lighting
- Floating Objects
- Object Intersections
- Overly Perfect Symmetry
- Repeated Micro-textures
- Artificial-looking Steam
- Unnatural Edge Sharpness

Quality evaluation should include both normal viewing distance and enlarged inspection when texture fidelity is important.



---

## Output

Creative reasoning should be completed before execution.

By default, the workflow should communicate the conclusions necessary for the next action.

A standard project summary may include:

- Project Definition
- Selected Direction
- Key Decisions
- Scene Locks
- Variable Assets
- Execution Plan

When the user requests analysis, the diagnosis and recommended correction should be presented before execution.

When the user requests direct generation or editing, reasoning may remain concise, but the complete workflow should still guide execution internally.

Detailed reasoning should be presented only when explicitly requested.

The same creative reasoning process applies consistently across image generation, image analysis, image retouching, image editing, style transformation and all other creative visual tasks.



---

## Guiding Principle

This workflow does not optimise prompts.

It optimises creative reasoning.

Better reasoning produces better decisions.

Better decisions create more coherent worlds.

More coherent worlds produce more believable, controllable and commercially useful images.
